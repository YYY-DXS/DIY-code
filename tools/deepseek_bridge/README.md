# DeepSeek 实时同步桥

在 Edge 里聊的内容会自动流进 `knowledge/deepseek/`，不用手动导出。

## 当前状态：已装好，日常零操作

- 浏览器脚本已装进 Tampermonkey（版本见脚本头部 `@version`）
- 服务已设成开机自动启动，关机重启后自己会跑起来
- 服务在后台运行，没有窗口，正常情况不用管它

验证方法：打开 chat.deepseek.com，右下角出现绿色小标签就说明通了。

## 目录说明

| 路径 | 说明 |
| --- | --- |
| `server.py` | 本机接收端，只监听 127.0.0.1:8765 |
| `userscript_template.js` | 用户脚本模板，`--setup` 时注入令牌和端口 |
| `autostart.vbs` | 开机自启脚本（已复制到 Windows 启动文件夹） |
| `start.cmd` | 手动启动服务（会留一个窗口，自启失效时用） |
| `stop.cmd` | 手动停止服务 |
| `restart.cmd` | 停止并重新启动（改过服务端代码后用这个） |
| `test_parse.mjs` | 离线回归测试，拿真实报文验证解析逻辑 |

运行数据在 `knowledge/deepseek/data/`：

- `bridge.log`：运行日志，能看到每条消息的写入时间
- `live_raw.jsonl`：抓到的原始报文，排查问题用

## 常见操作

**更新浏览器脚本**

脚本改动后重新生成并安装：先 `start.cmd --setup`，再打开
http://127.0.0.1:8765/ 点"安装同步脚本"，Tampermonkey 会提示更新，点更新即可。

**停止 / 恢复服务**

双击 `stop.cmd` 停止，双击 `start.cmd` 恢复。要想永久取消开机自启，
删掉启动文件夹里的 `DeepSeek同步桥.vbs`（在文件资源管理器地址栏输入
`shell:startup` 就能打开那个文件夹）。

**改了服务端代码之后**

双击 `restart.cmd`。浏览器脚本自带自动更新（`@updateURL` 指向本机服务），
服务端改了不用管，脚本改了一般会在一天内自动更新，急用就重新点一次安装链接。

## 置顶会话自动整理

浏览器脚本会把会话列表（含置顶标记）发给服务端，服务端自动重建
`knowledge/deepseek/置顶会话/`：

- 新置顶的会话会加进来，取消置顶的自动删掉
- 顺序跟着 DeepSeek 里的置顶顺序走
- 全自动，不需要定时任务，也不需要手动跑命令

**改了脚本想验证解析逻辑**

```
node tools/deepseek_bridge/test_parse.mjs
```

它会读取 `live_raw.jsonl` 里最近的流式报文，回放一遍并打印解析结果。

## 排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 右下角没有标签 | 脚本没运行 | 检查 Tampermonkey 是否启用、Edge 的"开发人员模式"是否打开，然后刷新页面 |
| 标签灰色"未启动" | 服务没在跑 | 双击 `start.cmd`，或重新登录一次 Windows |
| 标签"令牌错误" | 令牌不匹配 | 重新 `start.cmd --setup` 并重装脚本 |
| 标签绿色但内容不全 | DeepSeek 改了接口格式 | 看 `data/live_raw.jsonl`，按新格式调整 `userscript_template.js` 的解析部分 |

## 边界

- 单向同步：只能 DeepSeek → 本地，没有反向写入的接口
- 只在电脑上的 Edge 开着时工作，手机端聊的内容抓不到
- 打开旧会话时会把该会话的完整历史补齐，所以浏览一遍等于补一遍
- 依赖 DeepSeek 网页版的内部接口，官方改版后可能需要更新脚本
- 定期从 DeepSeek 导出的 zip 仍然是权威版本，重新导入时会以导出包为准，
  自动清掉同一条消息的实时副本，不会重复
