# 数据整理与迁移方案

## 1. 问题

一个长期使用的 Codex 工作环境并不只是"一个文件夹"。它通常由四类性质完全不同的
数据混在一起：

1. 你写出来的代码和生成物；
2. 与模型的历史对话（含个人隐私）；
3. 配置里的凭据（API Key、登录态、本机令牌）；
4. 完全可再生的缓存与依赖。

直接整目录复制，会同时带来三个后果：包体过大、隐私裸奔、密钥进仓库。因此本方案
先分类，再决定每一类的去向。

## 2. 四类模型

| 类 | 判定标准 | 典型内容 | 去向 |
| --- | --- | --- | --- |
| **A 代码** | 人写的、可读的、可版本化的 | 源码、脚本、配置模板、生成物 | 私有仓库 / 直接拷贝 |
| **B 隐私** | 含个人信息，泄露有实际后果 | 聊天记录、会话历史、记忆库 | 加密包，或移动硬盘 |
| **C 密钥** | 泄露即需要轮换 | `config.toml` 里的 API Key、`auth.json`、本机令牌 | 不打包、不入库，单独交接 |
| **D 缓存** | 删掉后能自动重建 | `node_modules`、venv、JDK/SDK、日志、插件缓存 | 不迁移 |

判定顺序很重要：**先判断是不是 C，再看是不是 B，最后才归到 A**。一个文件同时
像"配置"又像"代码"时，按更严格的类别处理。

## 3. 为什么"路径"是这类迁移的核心风险

Codex 工作环境里的脚本、快捷方式、开机自启项普遍写着绝对路径：

```text
C:\Users\demo\Documents\ChatGPT\New project\tools\bridge\server.py
```

新电脑用户名一旦不是 `demo`，这些路径全部失效。而最麻烦的是 `.vbs` 自启项：
它由 `wscript.exe` 静默执行，路径错了不会弹任何错误，表现为"装好了但没在跑"。

方案的处理方式：

1. 迁移包里记录旧用户名（`00-清单\环境信息.md`）；
2. 还原时若新旧用户名不同，对 `.ps1/.cmd/.vbs/.py/.json/.toml` 等文本文件做
   定向替换，跳过聊天记录与二进制素材；
3. `.lnk` 快捷方式通过 `WScript.Shell` 重新指向新路径；
4. 还原结束后明确提示"重启一次，看任务管理器里有没有 pythonw"。

## 4. 迁移包结构

```text
00-清单\                 环境快照、SHA256 清单、隐私提醒、剔除说明
01-项目源码\New project\  代码与工具
02-DeepSeek知识库\        聊天记录（B）
03-Codex工作区\           生成物（A）
04-Codex应用数据\.codex\  约定、规则、会话、记忆
05-启动项与快捷方式\      自启脚本与 .lnk
06-密钥\                  仅显式开启时存在（C）
```

编号即处理顺序：先代码、再隐私、再配置、最后自启。

## 5. 三条迁移路线

| 路线 | 适用 | 优点 | 代价 |
| --- | --- | --- | --- |
| 直接拷文件夹 | 新机用户名相同 | 零学习成本 | 会带上大量缓存 |
| 本工具 export/restore | 用户名不同、要可控 | 自动分类、改路径、校验 | 需要 PowerShell |
| 私有仓库 + 加密包 | 想长期可重复 | 换机一条 `git clone` | 首次配置成本高 |

三者可以混用：代码进仓库，隐私和密钥走移动硬盘。

## 6. 安全边界

- **密钥永不入库。** 一旦进入 git 历史，删除文件也不会消失，只能轮换密钥。
- **隐私默认加密。** `protect` 使用 AES-256-CBC + HMAC-SHA256，PBKDF2-SHA256
  12 万次迭代，随机 salt/IV；密码不落盘。
- **上传前看体积。** GitHub 单文件上限 100 MB，超过 50 MB 会告警；`-MaxFileMB`
  会在打包时剔除并在清单里记账。
- **不信任静默失败。** 还原后必须做一次重启验证，而不是只看脚本输出"成功"。

## 7. 验收

1. 桌面快捷方式能启动应用，热键有响应；
2. 知识库的索引文件内容完整；
3. 重启后任务管理器存在常驻进程；
4. 浏览器同步脚本显示已连通；
5. Codex 会话列表能看到旧机器的历史。

任何一项不通过，先用 `verify -Deep` 排除包损坏，再检查路径与用户名。
