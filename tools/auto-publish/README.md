# 自动推送

从本地知识库里发现新的 DIY 项目讨论，自动生成项目文档并推送到仓库。

## 怎么判断「有价值」

先过一道硬门槛：**必须命中 DIY 关键词**（模型、模组、外骨骼、ESP32、舵机、
3D打印、手工、飞艇、航模、无人机……），否则直接淘汰。这样能把
「VPN 教程」「街车价格」这类只有步骤、预算特征但和动手做东西无关的对话挡住。

过了门槛再打分（默认 **6 分**才推送）：

| 条件 | 加分 |
| --- | --- |
| 在 DeepSeek 里置顶 | +2 |
| 标题命中关键词 | +3（多个再 +1） |
| 原始需求命中关键词 | 每个 +1，最多 +2 |
| 回答里含材料清单／步骤／预算等方案要素 | +1 |
| 消息数 ≥ 10 | +1 |

没达门槛的不会丢，会记进 `state.json` 的候选清单，随时可以人工捞回来。

## 用法

| 文件 | 作用 |
| --- | --- |
| `只看不推.cmd` | 只列出会推送什么，不动任何文件 |
| `运行一次.cmd` | 立刻执行一次（生成文档 + 提交 + 推送） |
| `安装每日任务.cmd` | 注册每天 20:00 自动运行的任务 |
| `取消每日任务.cmd` | 取消该任务 |
| `run-silent.cmd` | 定时任务实际调用的入口，日志写进 `run.log` |

## 排除某个会话

```bash
python auto_publish.py --exclude <会话ID>
```

加进去的会话永远不会被推送。

## 注意

- 自动生成的是**草稿**，只包含讨论开头的需求与初步方案，会标注「待整理」。
- 已经人工整理过的项目（齐柏林飞艇、外骨骼、台历、航空模型）在脚本里登记过，
  不会重复推送。
- 脚本需要能访问仓库并推送，也就是依赖已经配好的 SSH 密钥。
