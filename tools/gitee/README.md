# 把项目上传到码云（Gitee）

## 为什么要你自己点一下

GitHub 在这台机器上被网络拦住了（网页超时、HTTPS 也超时），而 Codex 这边
现在没有联网权限。所以推送这一步必须由你执行——顺带说，这也更安全，
你的账号密码始终没经过我。

## 开始之前（只需做一次）

1. 打开 https://gitee.com 注册或登录（国内直连，不用梯子）
2. 右上角 `+` → **新建仓库**
3. 仓库名填一个好记的，比如 `new-project`
4. 可见性选 **私有**
5. **不要**勾选「使用 Readme 文件初始化这个仓库」——保持空仓库，否则推送会冲突

## 上传

双击 **`上传到码云.cmd`**，按提示填四项：

| 提示 | 填什么 |
| --- | --- |
| 码云用户名 | 你的登录名（不是昵称），比如 `yinghao` |
| 仓库名 | 刚才建的仓库名，直接回车默认 `new-project` |
| 显示名 | 提交记录里的作者名，直接回车用用户名 |
| 邮箱 | 直接回车用 `用户名@users.noreply.gitee.com` |

然后会要你登录：可能弹出窗口，也可能在命令行里问用户名密码。用你的码云账号登录即可。
密码会由 Windows 凭据管理器记住，下次不用再输。

成功的话窗口最后会显示「推送成功」和仓库地址。

## 以后怎么更新

再双击一次 `上传到码云.cmd` 就行 —— 脚本会自动把新改动提交并推送。

## 不会被上传的东西

- `knowledge/` 整个目录（你的 DeepSeek 聊天记录，含个人信息）
- `hanhua-kit/.recon/`、`hanhua-kit/out/`（第三方前端的文件）
- 各种 `__pycache__`、`*.sqlite`、`*.zip`

这些规则写在 `.gitignore` 和 `hanhua-kit/.gitignore` 里。想确认某个文件会不会
被传，可以让 Codex 帮你跑 `git check-ignore -v <文件名>`。

## 排错

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| `repository not found` | 仓库没建、名字写错，或用户名写错 | 回码云核对用户名和仓库名 |
| `Authentication failed` | 账号密码不对 | 重新运行一次，重新输入 |
| `non-fast-forward` / `rejected` | 远端仓库不是空的（建仓库时勾了初始化） | 把报错发我，加一步合并就行 |
| 卡在推送没反应 | 网络问题 | 检查码云能否在浏览器打开 |

日志存在同目录的 `push-log.txt`，出问题直接把它发给 Codex 即可。

## 想换成免密推送（可选）

这台机器上已经生成过一对 SSH 密钥：

    C:\Users\<用户名>\.ssh\id_ed25519.pub

把里面的内容复制到码云的「设置 → SSH 公钥」里，然后把脚本里的远端地址
从 `https://gitee.com/...` 换成 `git@gitee.com:...`，以后推送就不需要输密码了。
要换的话告我一声，我改脚本。
